## Reader's note (written by hand, not machine-generated)

### What changed from the first probe

The first run established that `lookup_all_teams.php?id=4659` returns English League 1, but
could not say whether `4659` was simply the wrong id — our mistake — or a correct id being
mis-served. Those have opposite fixes, so the question mattered. It is now answered:

**`4659` is TheSportsDB's own id for the Northern Irish Premiership**, per their league
directory. Nothing in `api/table.js`, `api/events.js` or `scripts/weekly-update.js` is
misconfigured, and changing the id would make things worse, not better.

### The fault is narrower than it first looked

Only `lookup_all_teams.php` is affected. The site's actual live path is healthy:

- correct `idLeague` (`4659`) and `strLeague` ("Northern Irish Premiership") on every row
- real fixtures — the last game of 25/26 and the first of 26/27
- the named opener matches our independently-entered `FIXTURES_2627` round 1 exactly

So the earlier worry — that the guards might be silently masking a permanent failover, with
the app quietly serving `data.js` forever while looking healthy — **is not happening**. The
live-data layer is working.

### What this rules out

Squad lists cannot be built from this API as things stand. Player records are only reachable
via `lookup_all_players.php?id={idTeam}`, and the only way to obtain NIFL `idTeam` values is
`lookup_all_teams.php`, which is the broken endpoint. There is no path from a working
endpoint to a squad.

### If squad data is wanted later

Two routes not tried here, both cheap to probe and neither requiring app changes:

1. `search_all_teams.php?l=Northern%20Irish%20Premiership` — league lookup by name rather
   than id, which may not share the id-based endpoint's fault.
2. `searchteams.php?t={club name}` per club — twelve calls, resolving `idTeam` by name and
   bypassing the league listing entirely.

Either would establish real `idTeam` values, after which the original question — is the
player data complete enough to build squads from — could finally be answered. Both are
diagnostics; neither has been built, and no ingestion should follow without the usual
`idLeague` validation on whatever comes back.
